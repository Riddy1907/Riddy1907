## Hi, ich bin Ridvan 👋

Ich baue mir Dinge, die ich selbst täglich benutze. Meistens entstehen sie rund
um die NAS bei mir zu Hause, auf der ein gutes Dutzend Dienste in Docker läuft —
Medien, Fotos, Dokumente, Haussteuerung. Die Regel dabei: es soll ohne Cloud
funktionieren, nach einem Stromausfall von allein wiederkommen, und beim
nächsten Mal noch nachvollziehbar sein. Deshalb liegt alles versioniert in einem
Repo, Zugangsdaten konsequent daneben statt darin.

### 🔧 Woran ich gerade baue

Eigenbau für das Homelab — die Repos sind privat, hier in Kurzform:

| Projekt | Was es macht |
|---|---|
| **ipod-sync** | Musik von der NAS auf einen klassischen iPod, ohne iTunes. Schreibt die iTunesDB direkt — die libgpod-Bindings für Python gibt es nicht mehr, also spiegelt es das C-Struct über `ctypes`. |
| **kinas-tools** | Eine Handvoll kleiner Web-Werkzeuge für den Alltag: Arbeitszeit, Tracker, Umrechner. Einzelseiten ohne Build-Schritt, dahinter eine schmale API, die JSON ablegt. |
| **scan_es2button** | Scannen auf Knopfdruck: Papier einlegen, Knopf am Scanner drücken, fertiges PDF liegt auf der NAS. Inklusive Leerseiten-Erkennung bei Duplex und Upload nach Immich. |
| **ntfy-melder** | Plugin, das mir aufs Handy meldet, wenn ein Download durch ist — einmal, nicht fünfmal. |

### 💡 Was mich daran interessiert

- **Self-Hosting und Automatisierung** — lieber eine eigene Lösung verstehen als
  ein Abo verwalten
- **Alte Geräte weiterbenutzen.** Ein iPod von 2006 spielt noch einwandfrei
  Musik; was fehlt, ist die Software drumherum. Also schreibt man sie.
- **macOS auf fremder Hardware.** Meine OpenCore-Konfiguration für ein
  MSI B460M Mortar liegt
  [öffentlich hier](https://github.com/Riddy1907/MSI-B460M-Mortar-Opencore-EFI).
- **Diagnose vor Reparatur.** Die meiste Zeit kostet nicht der Fix, sondern die
  falsche Fehlerannahme. Jedes Projekt hier hat deshalb eine README, in der
  steht, was *nicht* funktioniert hat und warum.
